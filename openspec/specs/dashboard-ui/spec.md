# dashboard-ui Specification

## Purpose
HTML-дашборд Instagram Tracker: два варианта UI (V2 по умолчанию и V1 классический), переключатель в шапке, навигация, обзор с фокусом на изменениях, селектор периода и списки пользователей. Генерация пишет index.html (V2) и index-v1.html (V1).

## Requirements
### Requirement: Две версии дашборда
Система MUST поддерживать два варианта UI: V2 (новый) и V1 (классический, текущая реализация на момент freeze). Генерация MUST создавать оба файла: `index.html` для V2 и `index-v1.html` для V1. Открытие дашборда по умолчанию MUST вести на V2 (`index.html`).

#### Scenario: После generate
- **WHEN** пользователь выполняет `generate`
- **THEN** в корне проекта появляются `index.html` (V2) и `index-v1.html` (V1)
- **AND** оба файла содержат актуальные данные одного и того же снимка

#### Scenario: Открытие по умолчанию
- **WHEN** пользователь открывает `index.html`
- **THEN** отображается UI V2

### Requirement: Переключатель версий в шапке
Каждая версия UI MUST показывать в шапке справа явную кнопку-ссылку на другую версию. На V2 текст MUST быть «← Классический вид» и вести на `index-v1.html`. На V1 текст MUST быть «Новый вид →» и вести на `index.html`. Переключение MUST NOT требовать повторной генерации или localStorage.

#### Scenario: С V2 на V1
- **WHEN** пользователь на V2 нажимает «← Классический вид»
- **THEN** открывается `index-v1.html` с тем же набором данных снимка

#### Scenario: С V1 на V2
- **WHEN** пользователь на V1 нажимает «Новый вид →»
- **THEN** открывается `index.html` (V2)

### Requirement: Full-width layout V2
Основная область контента V2 MUST занимать всю доступную ширину справа от сайдбара. V2 MUST NOT ограничивать main-контент фиксированным `max-width` вроде 1200px, оставляющим пустое поле справа на широких экранах.

#### Scenario: Широкий монитор
- **WHEN** пользователь открывает V2 на экране шире ~1400px
- **THEN** карточки обзора и списки тянутся до правого края окна (с разумными внутренними отступами)
- **AND** справа нет большой пустой колонки из-за max-width контейнера

### Requirement: Визуальный язык V2 Dark Refined
V2 MUST использовать тёмную тему с одним основным акцентным цветом (бирюза/teal). V2 MUST NOT использовать эмодзи как основные иконки навигации и MUST NOT применять пёструю многоцветную палитру акцентов (в т.ч. фиолетовый glow текущего UI). Нейтральные бейджи с числами — допустимы.

#### Scenario: Сайдбар без визуального шума
- **WHEN** пользователь смотрит сайдбар V2
- **THEN** пункты навигации текстовые, без эмодзи-иконок
- **AND** активный пункт выделен спокойным акцентным фоном/цветом
- **AND** бейджи счётчиков нейтральные (не разноцветные)

### Requirement: Навигация V2 — sidebar + страницы
V2 MUST сохранять модель «сайдбар + отдельные представления». Группы MUST включать: Главное (Обзор), Анализ, Изменения, Списки. Группа «Списки» MUST быть свёрнута по умолчанию, чтобы уменьшить число видимых пунктов.

#### Scenario: Первый взгляд на навигацию
- **WHEN** пользователь открывает V2
- **THEN** видны группы Главное, Анализ, Изменения
- **AND** группа Списки свёрнута и раскрывается по клику
- **AND** клик по пункту открывает соответствующее представление

### Requirement: Обзор V2 — сначала изменения
Экран «Обзор» в V2 MUST ставить блок изменений за выбранный период выше статичных метрик «Сейчас». При выбранном снимке сравнения MUST показывать крупные +/− (новые / ушедшие подписчики) и четыре кликабельные карточки изменений. Карточки MUST вести в соответствующие списки изменений.

#### Scenario: Есть снимок для сравнения
- **WHEN** выбран период сравнения и есть предыдущий снимок
- **THEN** вверху обзора отображаются изменения (+/−) и четыре карточки (новые подписчики, отписались, новые подписки, вы отписались)
- **AND** ниже — метрики текущего состояния (подписчики, подписки, взаимные, не подписаны, фанаты)
- **AND** клик по карточке изменения открывает соответствующий список

#### Scenario: Нет снимка для сравнения
- **WHEN** нет доступного снимка для сравнения
- **THEN** обзор показывает понятное сообщение об отсутствии сравнения
- **AND** метрики «Сейчас» остаются доступны

### Requirement: Селектор периода V2
V2 MUST предоставлять компактный селектор периода сравнения (пресеты вроде неделя / месяц / 3 мес / год / всё время и/или выбор конкретного снимка). Активный пресет MUST выделяться одним акцентным стилем. Рядом MUST отображаться дата выбранного снимка и длина периода в днях, когда сравнение активно.

#### Scenario: Выбор недели
- **WHEN** пользователь выбирает пресет «Неделя»
- **THEN** для сравнения берётся ближайший подходящий прошлый снимок
- **AND** UI обновляет блок изменений и списки requiresChanges
- **AND** показана подпись с датой снимка и числом дней

### Requirement: Списки V2 — богатые строки
Списки пользователей в V2 MUST показывать богатые строки: аватар, отображаемое имя, @username, доступную статистику (подписчики/посты при наличии), кнопку «Открыть» на профиль Instagram. Список MUST поддерживать поиск по имени и username. Деактивированные профили MUST быть визуально приглушены с одним текстовым бейджем статуса.

#### Scenario: Просмотр списка
- **WHEN** пользователь открывает любой список (анализ, изменения или полный)
- **THEN** каждая строка показывает аватар (или fallback-инициал), имя, @username и кнопку «Открыть»
- **AND** при наличии данных enrichment показываются счётчики
- **AND** поиск фильтрует список по имени и username

#### Scenario: Деактивированный профиль
- **WHEN** у пользователя `status = deactivated`
- **THEN** строка приглушена
- **AND** отображается текстовый бейдж о деактивации
- **AND** MUST NOT использоваться пёстрая иконка вместо бейджа

### Requirement: Сохранение поведения V1
V1 MUST сохранять текущее пользовательское поведение дашборда на момент freeze (сайдбар, обзор, периоды, списки, поиск, enrichment-поля). Изменения V2 MUST NOT ломать или удалять V1 в рамках этого change.

#### Scenario: Откат пользователем
- **WHEN** пользователю не нравится V2
- **THEN** он может открыть V1 через переключатель или напрямую `index-v1.html`
- **AND** все ключевые разделы V1 остаются доступны как до редизайна
