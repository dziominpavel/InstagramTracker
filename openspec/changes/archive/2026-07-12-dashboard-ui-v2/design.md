## Context

Instagram Tracker генерирует один интерактивный HTML-дашборд из `app/dashboard.py` (большой inline HTML/CSS/JS-шаблон). Данные: текущий снимок + история для client-side сравнения периодов, enrichment (аватарки, имена, статусы).

Пользовательский фидбек по текущему UI:
- слишком много пунктов сайдбара;
- сравнение периодов неудобное;
- списки неудобны;
- визуально устаревший / пёстрый (эмодзи, много цветов, глаз не знает за что зацепиться);
- справа пустое место из-за `max-width`.

Согласованные решения (brainstorm + Visual Companion):
- стиль **Dark Refined**;
- layout **sidebar + pages**;
- обзор **сначала изменения**;
- списки **богатые строки**;
- dual UI **V2 default + V1 rollback**;
- переключатель в шапке справа;
- full-width.

## Goals / Non-Goals

**Goals:**
- Выпустить V2 с заметно лучшей юзабилити и спокойным визуалом.
- Сохранить мгновенный откат на V1 без git/терминала для пользователя.
- Не менять pipeline данных (import → snapshot → enrichment).

**Non-Goals:**
- Светлая тема.
- Удаление V1 в этом change.
- Новые метрики/аналитика сверх текущих списков.
- Переписывание на React/отдельный frontend-стек.
- Visual Companion / Superpowers как runtime-зависимость продукта.

## Decisions

### 1. Два HTML-файла вместо одного с JS-toggle
- `index.html` → V2, `index-v1.html` → V1.
- Переключатель = обычные ссылки в шапке.
- **Почему:** проще отладка, мгновенный откат, нет localStorage-магии, файлы независимы.

### 2. Модули `dashboard_v1.py` / `dashboard_v2.py` + тонкий `dashboard.py`
- V1 = freeze текущего шаблона.
- V2 = новый шаблон.
- Общая сборка payload (counts/lists/snapshots) остаётся общей, чтобы не дублировать бизнес-логику.
- **Почему:** чистый откат кода и возможность позже удалить один модуль.

### 3. Dark Refined визуал
- Фон charcoal, один акцент teal/бирюза, без purple glow и эмодзи-навигации.
- **Почему:** снижает визуальный шум; совпадает с выбранным макетом C.

### 4. Overview-first changes
- Иерархия: period bar → +/− → 4 change cards → metrics «Сейчас».
- **Почему:** главный сценарий — «что изменилось после нового экспорта».

### 5. Списки свёрнуты в сайдбаре
- Analysis + Changes всегда видны; Followers/Following/Blocked/… под «Списки ▾».
- **Почему:** закрывает боль «слишком много пунктов».

### 6. Full-width
- Убрать `max-width: 1200px` у main; оставить padding.
- **Почему:** прямое требование пользователя.

### 7. Dev rollback
- Перед выносом V1 — git tag `dashboard-v1-freeze` (по запросу пользователя при коммите).
- Пользовательский rollback — UI switcher / `index-v1.html`.

## Risks / Trade-offs

| Риск | Митигация |
|------|-----------|
| Дублирование HTML/JS между V1 и V2 | Общий payload builder; UI-шаблоны раздельно осознанно |
| Расхождение данных между двумя файлами | Одна функция generate пишет оба из одного payload |
| V2 регрессии в period/compare логике | Переиспользовать существующие JS-алгоритмы сравнения, менять оболочку |
| Большой diff в одном PR | Freeze V1 отдельным шагом, затем V2 |

## Migration Plan

1. Вынести текущий шаблон в `dashboard_v1.py` без визуальных изменений.
2. Научить generate писать `index-v1.html` (+ временно тот же контент в `index.html` или сразу V2).
3. Добавить V2 шаблон и сделать `index.html` = V2.
4. Добавить ссылки-переключатели в оба UI.
5. Обновить README.
6. После решения пользователя — отдельный change на удаление одной версии.
