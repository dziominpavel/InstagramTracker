## Context

Дашборд показывает сырые списки экспорта Instagram и diff снимков рядом. «Заявки» (`recent_follow_requests`) не содержат статуса pending/accepted — принятые остаются в файле. «Недавно отписаны» (файл IG) и «Вы отписались» (diff `following`) — одно направление из двух источников; после выбора единого источника истины UI должен опираться только на diff снимков, как остальные вкладки «Изменения».

## Goals / Non-Goals

**Goals:**

- Показывать в «Заявках» только профили, которых нет в текущих `followers`.
- Переименовать «Отписались» → «Отписались от меня» везде в UI (V1/V2).
- Убрать вкладку «Недавно отписаны»; единственный UI для «я отписался» — «Вы отписались» (diff).

**Non-Goals:**

- Не чинить расхождение счётчика подписчиков экспорт vs UI Instagram.
- Не менять логику «новых подписчиков» по timestamp.
- Не удалять парсинг `recently_unfollowed_profiles.json` из пайплайна снимка (файл может оставаться в snapshot для совместимости).
- Не вводить статусы заявок beyond «есть в followers / нет».

## Decisions

### 1. Фильтр заявок на этапе `build_payload`

- **Решение:** в `app/dashboard.py` при сборке `lists.recent_follow_requests` исключать username, уже присутствующие в `snapshot.followers` (сравнение по `username` / id, как в остальном дашборде).
- **Почему:** один раз на генерацию; V1 и V2 получают уже отфильтрованный список; бейдж счётчика совпадает с видимыми строками.
- **Альтернатива:** фильтр только в JS — дублирование в двух шаблонах, риск расхождения бейджа.

### 2. Единый источник «я отписался» = diff снимков

- **Решение:** удалить tab `recently_unfollowed` из `TABS` в V1 и V2; не показывать этот список в навигации и на обзоре V1 (если есть карточка/метрика). Список изменений `lost_following` («Вы отписались») без смены смысла.
- **Почему:** симметрия с «Отписались от меня» и остальными «Изменения»; период «Сравнить с» остаётся единственной шкалой времени.
- **Альтернатива (отклонена):** оставить файл IG как fallback при пустом diff — снова два источника и путаница.

### 3. Что делать с полем в payload / снимке

- **Решение:** ключ `recently_unfollowed` в snapshot и при желании в `DATA.lists` можно оставить для обратной совместимости старых HTML, но UI MUST NOT иметь на него вкладку. Предпочтительно не включать в `lists` для новых generate, чтобы бейджи/обзор не ссылались на мёртвые данные — минимально: убрать из TABS и любых кликабельных карточек.
- **Почему:** меньше сюрпризов в UI; парсер не трогаем.

### 4. Переименование

- **Решение:** все пользовательские строки «Отписались» (вкладка, desc, карточка обзора) → «Отписались от меня» в V1 и V2. «Вы отписались» без изменений текста.
- **Почему:** явно направление «они → от меня».

## Risks / Trade-offs

- [Риск] Исторические отписки только из файла IG (до первого снимка) больше не видны в UI → Mitigation: осознанный trade-off; дальше покрывается diff между выгрузками.
- [Риск] Заявка от человека, которого ещё нет в followers, но уже приняли с задержкой экспорта → Mitigation: приемлемо; при следующей выгрузке пропадёт из списка.
- [Риск] Старые сгенерированные HTML сохранят старую навигацию → Mitigation: нужен повторный `generate`.
